# レイアウト検査の仕様

`mise run check-layout` は Chrome で実際に描画し、フォントと画像の読み込み後に改行・配置・表記を検査します。実装は [scripts/check-layout.cjs](../scripts/check-layout.cjs) です。実行手順と出力先は [README](../README.md#検査結果と原寸画像を確認する) を参照してください。

検査エラーはすべて終了コード 1 になり、`mise run pdf` の PDF 生成も止めます。人が判断する `Space review` の空白候補と `demonstrative` の表現候補は、この停止条件に含めません。

## 各検査の条件

### demonstrative (確認候補)

スライド本文では代名詞を使わず、対象を具体名で示します。描画テキストを日本語の `Intl.Segmenter` で単語に分け、`その`・`この`・`それ`・`これ`・`あの`・`あれ`・`当該` と一致する語を `review.md` の該当ページと `lines.json` の `languageReview` に確認候補として出します。ターミナルでは `REVIEW demonstrative` と表示し、エラー数・終了コードには加えません。

対象と除外は `parenthesis-width` と共通です。コード・数式・URL・角括弧内の引用リンクを除き、speaker note の HTML コメントも描画本文に含まれないため対象外です。通常リンクの表示文字列や太字をまたぐ語は対象です。`その他` のように別の 1 語と判定される複合語は候補にしません。

分かち書きは品詞・指示対象を確定する処理ではありません。例えば普通名詞の `このはずく` も `この` で分割されるため、例外なく停止できる規則にはできません。固有名詞や語の引用かどうかは人が判断します。`これら`・`それぞれ`・`そのため` のように一語になる形、画像内の文字などは検出を保証しません。候補ゼロを代名詞ゼロの保証にせず、本文の通読でも確認してください。

### layout-sample-missing / layout-class-unregistered / layout-class-stale

`themes/ly.css` の `@layouts` コメントに配置用クラス、`@utility-classes` コメントに分類・背景色・デバッグなどの補助クラスを空白区切りで宣言します。`@utility-classes` だけ末尾 `*` による前方一致を使えます。宣言した各名前・パターンに対応するテーマ selector が必要です。

Chrome の CSS parser でテーマを読み、`section` / `:root` と同じ compound selector のクラス（`:is`・`:where`・`:not` 内も含む）を照合します。子要素・属性値・`:has` 内の子孫クラスは数えません。クラス名は ASCII 英小文字で始まる英数字・`_`・`-` とし、CSS のエスケープ表記は扱いません。`layout-example`・`paired-definitions` のように検査専用でテーマに selector がないクラスは宣言しません。

`@layouts` の全クラスについて、描画した `slides/example/slides.md` の section に少なくとも 1 回の使用を要求します。Markdown のコード例やコメントに名前を書くだけでは通りません。資料を指定して検査する場合も、このリポジトリ全体の検査を実行し、最初の資料の slide 0 に報告します。見本を増やすときは配置に合う本文・図表を用意し、原寸画像でも確認してください。クラスが付くだけで内容の適合性を保証する検査ではありません。

### unbalanced-lines

数式内部の注釈や複数行の式は本文の行長比較から除外します。数式のはみ出しは `math-overflow` などで検査します。

2 行目以降の最短行と同じ要素の最長行を比べます。見出しは 60% 未満、本文・箇条書き・表セル・キャプションは 25% 未満でエラーです。短い途中行も対象で、自動・明示の両改行を調べます。flex/grid の見出しは題目と副題を独立して測り、大きな題目が副題の改行を隠さないようにします。

### midword-wrap

自動改行が `Intl.Segmenter` の単語内部に入るとエラーです。日本語は `ja`、英語などは各 section の `lang` で分割します。英単語・リンク・コードも対象で、隣接行と分割された単語を記録します。`<br>`・`<wbr>` は明示的な区切り、インライン数式は単語の区切りとして扱い、数式内部は検査しません。単語境界・句読点での折り返しは対象外です。`意図 | どおり` は通り、`意図ど | おり` はエラーですが、単語境界をまたぐ句全体の自然さは判定しません。

### title-wrap

`section > h2` の題目・副題の各描画行を測り、どちらかが複数行になるとエラーです。表紙も同じ `h2` 構造なら対象です。論文表紙の `h1` はこの検査の対象外です。

### heading-soft-wrap

太字だけの段落（`p > strong:only-child`）の自動折り返しをエラーにします。著者が `<br>` で指定した改行は許容しますが、その前後がさらに自動折り返しされる場合はエラーです。太字だけではない見出しや画像内の文字は対象外です。

### table-header-wrap

表の見出しセル（`th`）が、明示的な改行も含めて複数行ならエラーです。画像として埋め込まれた表の文字は測りません。

### text-overlap

異なるテキスト要素の描画範囲が縦横とも 2px を超えて交差する場合、フッターも含めてエラーです。Marpit のページ番号（`section[data-marpit-pagination]::after` に数字・空白・`/` で表示するもの）も字形を測ります。同じ要素内の文字同士、文字と画像、画像内部の文字、その他の疑似要素は対象外です。

### text-overflow

文字が本文ボックスまたはスライド外へ 1px を超えて出るとエラーです。画像より広いグリッドのキャプションは、そのキャプション自身のボックスで検査します。

### box-overflow

図（`img`）・比較枠（`blockquote`）のボックスがスライドの各辺から 1px を超えて出るとエラーです。DOM にない背景画像は検査しません。

### footer-overflow

本文の描画文字・画像・表・数式が、footer またはページ番号の実文字に縦横 2px の余白内で交差するとエラーです。footer 要素の幅全体は侵入禁止帯にしません。右下バナーと左下著作権のように横方向に離れた配置を許容します。Marpit のページ番号は `text-overlap` と同じ方法で疑似要素の字形を測ります。

footer の有無にかかわらず、内容が下端安全線を 1px 超える場合もエラーです。安全線はスライド下端から共通 `--slide-padding`（`ly` は 20px）、未定義なら section の `padding-bottom` を引いた位置です。表紙の本文配置用の大きな padding とは区別し、下端から 24px のバナーを移動させません。header・footer・ページ番号・情報分類・背景装飾は本文から除外します。画像・表・数式はボックス、文字は描画行を測り、画像内部の余白と一般の疑似要素・背景画像の実内容は判定しません。

### math-label-gap

同じ MathJax の表示数式内で、下括弧の注釈に属する `mtext` の実描画矩形をまとめ、すべての注釈ペアを比べます。SVG の日本語 text と英数字の path の両方を含み、phantom 自体は数えません。矩形の交差、または矩形間の最短距離が大きい方の注釈の 0.25em 未満（計測誤差 0.1px）ならエラーです。em は SVG の変換を含めた実サイズから得ます。上下にずらした注釈も、実際の距離で判定します。

同じ注釈内に複数の `text` がある場合は一つの外接矩形とします。下括弧は MathJax SVG の munder と brace glyph で識別し、通常の添字・上括弧・画像内の文字・別数式間は対象外です。`text` を使わない数学記号だけの注釈や将来の MathJax 出力構造は検出を保証しません。余白を広げるだけで式を不自然に伸ばさず、原寸画像で式と注釈の対応を確認してください。

### math-overflow

MathJax の表示数式が、本文の下 padding の上端から 1px を超えて出るとエラーです。下括弧の注釈どうしは `math-label-gap` でも検査し、原寸画像で確認します。

### column-alignment

同じ行で横並びになる section 直下の本文ブロックは、列の先頭の描画上端を比べ、差が 2px を超えるとエラーです。同じ横位置で縦積みしたブロックは一つの列とし、全列をまたぐブロックで比較する帯を区切ります。図が先頭の列と `align-self: center` の列も対象です。図対本文は先頭行ボックス（文字の上下の余白を含む）と画像の実描画上端、本文どうしは先頭の字形上端を比べます。

画像が先頭で画像 1 枚だけの列と、画像のない本文列では、画像の実描画下端と隣列の最終本文行ボックス下端の差が 2px 以内の配置も認めます。通常は画像上端が本文先頭より 2px を超えて上に出る配置を認めません。ただし grid / flex の本文列が 1 ブロックで `align-self: end` を明示した場合は、本文より高い画像も下端一致で認めます。中央揃え自体を例外にはせず、キャプション下端や空の本文ボックス下端でも代用しません。

`object-fit: contain` / `scale-down` は自然寸法の縦横比・拡大制限・border・padding・`object-position` の割合 / px 指定から枠内の余白を計算します。画像ファイル内部の白・透明余白、マスク、変形、入れ子列、複雑な `object-position` の式は判定しません。表紙・高橋メソッド・プロフィール・テンプレート見本は対象外です。`paired-definitions` の高さ検査も併用します。

### paired-definition-alignment

`paired-definitions` クラスのあるページで、先頭 2 個の blockquote の先頭段落を定義文として調べます。定義文が 2 個揃わない場合、または段落の高さ差が 2px を超える場合はエラーです。列の上端は `column-alignment` が検査するため、両者を併用します。原寸画像でも行数と開始位置を確認してください。

### large-prose-gap

同じ親の隣り合う本文段落・リスト（`p`・`ul`・`ol`）で、指定マージンに加えて 1 行分を超える空白があるとエラーです。指定マージンは後続要素の上 margin と前要素の下 margin の大きい方です。図を含むブロックのキャプション間隔は図・出典間隔検査で扱います。

### list-item-gap

同じ親の隣り合うリスト項目（`li + li`）・本文段落（`p + p`）で、横方向に範囲が重なる要素のボックス間隔を測ります。本文ページの `--list-item-gap` を CSS で px に解決し、最小値の 2 倍を 2px 超えるとエラーです。個別ページ・リストの余白を広げても基準は緩みません。

直後に段落・リスト・表を持つ太字だけの段落と、太字見出しに子リストが続く項目はグループ見出しとして除外します。図を含む項目・図キャプション、表紙・プロフィール・高橋メソッド・テンプレート見本も対象外です。別の親に分かれた項目やボックス内部の余白は測りません。`group-gap` と `large-prose-gap` は併用します。

### group-gap

直後に段落・リスト・表が続く太字だけの段落をグループ見出しとし、直前グループ（段落・リスト・表）からの距離を測ります。太字全体をリンクで囲む段落と太字内にリンクのある段落も対象ですが、太字の外に本文が混じる段落は対象外です。

直前の兄弟が画像のない本文ボックスの場合は、先に置いた兄弟ボックスの末尾グループのうち、見出しと横方向に重なり、見出しより上で最も下まで達するものから測ります。全幅見出しは隣列のキャプションも含め、片側だけの見出しは隣列を含めません。

基準間隔は各 section の computed `--list-group-gap` の最大値です。基準未満ならエラーで、ページごとに値を下げても基準は下がりません。同じ親要素と前後グループの種類を持つ見出しでは、ページ内中央値を出し、それらのページ間中央値（基準間隔を下限とする）から 2px を超えてずれるページもエラーです。

題目直後・図キャプション内・単独列の見出し、表紙・プロフィール・高橋メソッド・テンプレート見本は除外します。構造で識別できない見出し・キャプションは検出せず、すべての section で値を小さく上書きした場合は元の基準値を復元できません。

### group-gap-config

検査対象のグループ見出しがあるのに、資料または対象 section の `--list-group-gap` が数値として得られない場合はエラーです。テーマに基準値を定義してください。

### sparse-body

本文の文字・画像・数式の下端が、見出し下の利用可能高の 75% に届かないとエラーです。section 直下に横並びのブロックがある場合は、列ごとに 60% 以上の高さまで内容が届く必要があります。同じ横位置に積んだブロックは同じ列とし、下に全列をまたぐ本文・数式が続く場合はその上端までを列の利用可能高とします。空のボックスの高さは算入せず、測定値は `lines.json` の `bodyFill` に残します。

表紙・高橋メソッドと、`layout-example` を付けたテンプレート見本は対象外です。入れ子のグリッド内や図内部の余白は判定しません。内容の最下端を測る検査であり、途中の空白面積は測りません。空のボックスや無意味な装飾を足さず、比較・図解など内容に合う配置へ直してください。`layout-example` は背景・クラス名だけを示す見本に限ります。

### font-size-mismatch

同じ資料の本文ページ間で、見出し・説明見出し・本文・入れ子・図キャプション・図の出典・引用・情報分類・ページ番号の実際の文字サイズを比べます。同じ役割で `font-size` が一致しないとエラーです。表紙・高橋メソッド、プロフィールの人名・連絡先など別の役割は対象外です。

### unbracketed-citation

本文・図の年表記（`’YY` / `'YY`）付き引用リンクに、表示用の角括弧がないとエラーです。`[[著者+ 会議’年](URL)]` のように、リンクを外側の括弧で囲みます。

### linked-citation-bracket

年表記付き引用リンクの表示文字列に角括弧が含まれるとエラーです。外側の括弧は表示だけに使い、リンクに含めません。

### bundled-citation

一つの引用リンク内に複数の `Author+` 表記があるとエラーです。研究ごとにリンクを分けます。同一著者の複数論文は角括弧 1 組にまとめ、各文献だけを個別リンクにできます。著者・年・リンク先の対応は原典と照合してください。

### missing-metric-citation

段落・箇条書き中の BLEU の直後に著者・年付きの引用リンクがないとエラーです。正式名称だけの説明や、離れた位置の引用では通りません。他の指標や、リンク先が原論文であるかは自動判定しません。

### figure-caption-missing

`Figure from` で始まる段落に、`Figure from [引用]: 説明` という形式・リンク・空でない説明を要求します。説明内容の妥当性は人が確認します。

### figure-source

引用図のブロックに出典がない場合や、図ブロック内のリンク付き段落が出典形式でない場合はエラーです。複数パネルには共通の出典行も使えます。プロフィールの写真・サムネイルは引用図として扱いません。

### figure-source-gap

出典行から最も近い図までの距離が、出典の行高の 2 行分を超えるとエラーです。行高を取得できない場合は文字サイズの 1.5 倍を 1 行分とします。各出典と原典の図の対応は人が確認してください。

### redundant-source

`出典:` / `Source:` で始まる独立した段落をエラーにします。図に隣接した `Figure from [引用]: 説明` にまとめてください。

### axis-outside-figure-caption

`横軸:`・`縦軸:`・`左縦軸:`・`右縦軸:`・`x軸:`・`y軸:` のラベルに説明が続く定義を、出典外でエラーにします。全角コロン・空白・英字の大小も許容します。軸説明は同じ図の出典 blockquote または出典行内に置いてください。「横軸の区間ごとに特定正解率 (縦軸) を集計」のような本文の参照文は許容しますが、出典内の説明の代わりにはなりません。軸の語句や定義ラベルがない説明は検出できません。

### axis-pair-missing

`Figure from` 出典内に横軸 / x 軸・縦軸 / y 軸の片方だけがあるとエラーです。同じ図の出典にもう一方の説明も置いてください。本文側の参照文では代用できません。

### parenthesis-width

スライドの描画テキストの全角括弧 `（`・`）` は、中身にかかわらず 1 文字ごとにエラーです。日本語も `特定正解率 (縦軸) を集計` のように半角括弧で囲みます。

対象は見出し・段落・箇条書き・表セル・キャプション・header/footer の DOM テキストで、太字などのインライン要素をまたいでも判定します。数式、インライン・ブロックコード、URL の表示文字列（`スキーム://`・`www.` から空白まで。英字の大小は不問）、角括弧内の引用リンクは除外します。通常リンクの表示文字列は対象です。

リンク先 URL・画像の代替テキスト・画像 / SVG 内の文字・疑似要素・描画時に失われたソース空白・括弧の対応は検査しません。`terms.json` の定義を変更する検査ではありません。

### parenthesis-spacing

`(` の前と `)` の後に日本語・ラテン文字・数字がある場合は、半角スペースを 1 個置きます。括弧のすぐ内側の空白と、`)` から句読点などの約物（Unicode の句読点類）・行末までの空白はエラーです。改行で区切った別の行には前後のスペースを要求しません。対象と除外は `parenthesis-width` と同じです。

### incomplete-necessity

段落・箇条書きが裸の「必要」で終わるとエラーです。「〜が必要」「〜は必要」「〜する必要あり」「〜する必要がある」は対象外です。末尾の句点の有無にかかわらず検査します。

### inconsistent-term-definition

資料と同じディレクトリの `terms.json` が固定の用語定義の正本です。登録用語を `用語: 定義`、`用語 (定義)`、`解決する問題: 定義 (用語)` の形式で書いた場合、内容が正本と異なるとエラーです。検査時には空白・英字の大小・コロンと括弧の全角半角を正規化しますが、定義は言い換えないでください。全角括弧は別の `parenthesis-width` でエラーになります。

### term-casing

資料の `terms.json` のキーを英字の大小の正本とします。題目・見出し・本文・キャプションで大文字小文字を無視して一致し、実際の大小がキーと違う場合はエラーです。`Atomic Layout` に対する `Atomic layout` などを検出します。キーが `Semantic drift` なら、その大小を維持します。

語間の空白と明示改行は正規化します。日本語に続く英語や複合語内も、キーと大小を無視して一致する部分は対象です。コード・数式・URL・角括弧内の引用リンクは `parenthesis-width` と同じ方法で除外し、対象論文固有の大小を持つ表紙（`paper-title`）の `h1` も除外します。登録用語の出現そのものは要求せず、綴り違いや除外部分をまたぐ用語は検査しません。

### missing-term-definition

登録された説明必須の用語は、正本どおりの定義が資料内に少なくとも一度必要です。定義がないと資料全体のエラー（slide 0）として報告します。重複掲載は必須ではありません。登録外の概念の欠落や説明の妥当性は人が確認します。

### underbrace-mathclap

[Marp の数式検証プラグイン](../scripts/check-math.cjs) が変換時に検査します。下括弧は `\underbrace{式}_{\mathclap{注釈}}` と書き、注釈全体を `\mathclap` で包んでください。コード内の TeX は対象外です。注釈どうしの衝突は `math-label-gap` で検査します。下端の余白と注釈の読みやすさも原寸画像で確認します。

## Space review の出力を読む

`review.md` の各ページに空白候補を列挙し、同じ番号を `slide-N-space.png` に着色して寸法を表示します。通常の `slide-N.png` と見比べ、図の下や列間の空白が意図した配置か判断してください。表紙・テンプレート見本も候補の出力対象で、候補数は合否に使いません。

本文領域は左右の padding 内、タイトル行の下端（上 padding より下）から下 padding または footer 上端までです。テキストの描画行、画像の実描画矩形（`object-fit: contain` / `scale-down` を含む）、表・数式・SVG を占有領域として 8px 格子へ切り上げます。空いた矩形のうち他の候補に包含されないものを出力します。閾値は幅 160px 以上かつ高さ 48px 以上、または本文面積の 1.5% 以上です。候補どうしは重なる場合があります。座標はスライド左上を原点とする px で、格子による境界誤差は各辺 8px 未満です。

`spaces.json` の `slides` には次の測定値を保存し、同じ値を `Space review` に表示します。

| データ                                   | 読み取れること                                                    |
| ---------------------------------------- | ----------------------------------------------------------------- |
| 候補矩形・上下左右の近傍                 | 辺と交差する最も近い内容の文字列。候補の位置を照合                |
| section 直下の兄弟列の内容上端・下端と差 | 列ごとの内容の揃い方                                              |
| 列行から最初の全幅ブロックまでの間隔     | 最も深い列の描画下端と、後続ブロックの描画上端・間隔（`rowGaps`） |
| 同じ親の連続ブロック間隔                 | `--content-gap` / `--list-item-gap` / `--list-group-gap` との比較 |
| 図とキャプションの距離                   | 同じ図ブロック内の画像ごとの距離                                  |

`rowGaps` は section 直下で縦方向に重なる兄弟列の最深の描画下端から、最初の全幅ブロックの描画上端までの距離です。全幅は本文の左右端から 2px 以内とし、同じ横位置に積んだブロックを同じ列にまとめ、3 列以上も後続ブロックごとに 1 件へまとめます。後続ボックス内部の上余白は間隔に含みます。8px 格子への丸めは行いません。太字と本文が混じる段落も測りますが、直前列の説明に続く数式など短い間隔が意図的な場合もあるため、`--list-group-gap` との比較は確認候補に留め、エラーにしません。入れ子列と全幅でない後続ブロックは対象外です。

画像内部の白・透明余白、マスク、変形、複雑な `object-position`、疑似要素・背景画像の実内容は測りません。表・数式・SVG は外接矩形全体を占有領域とするため、その内部の空白も対象外です。行末の余白や意図的な中央配置も候補に含まれます。

## 既知の限界と検査の保守

検査合格は読みやすさの保証ではありません。文節の切れ方、図の読みやすさ、キャプションの配置、前後ページの文字サイズ・節間・引用位置を原寸画像で比較します。Codex / Claude Code は原典も確認してください。候補ゼロや一覧画像だけで確認を終えないでください。

`ly` テーマは日本語に `word-break: auto-phrase`、短い最終行を避ける調整に `text-wrap: pretty`、副題に `text-wrap: balance` を使います。これらも不自然な改行をすべて防ぐ保証はありません。エラーが出たら文字サイズや閾値を下げず、文章・ボックス幅・図の配置を見直します。複数行の本文は意味のまとまりと各行の長さを揃え、指定された改行は `lines.json` と原寸 PNG の両方で確認します。

参考: [Chrome の pretty 解説](https://developer.chrome.com/blog/css-text-wrap-pretty)、[BudouX の文節分割](https://github.com/google/budoux/blob/main/README.md)、[Chromium の行分割実装](https://github.com/chromium/chromium/blob/main/third_party/blink/renderer/core/layout/inline/score_line_breaker.cc)。

フォント・画像の読み込み失敗や実行エラーも非ゼロで終了します。Marp CLI 同梱の Puppeteer を使うため追加インストールは不要です。Marp 更新時や検査スクリプト変更時は `mise run test-layout` を実行してください。新しい見た目の不具合を検査に追加するときは、実際の不具合と正常例を回帰テストにし、修正前に PDF 生成が停止し、修正後に通ることを確認します。情報分類の検証や Marp 設定を変更した場合は `mise run test` も実行します。
